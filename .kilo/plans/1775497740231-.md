# Saccoup Payment System Analysis

## Questions Answered

### 1. How does saccoup handle payments, receipts and invoices?

**Payments**: 
- Tracked via `contributions` table in database
- Payment methods: MTN MoMo, Airtel Money, Cash, Bank Transfer
- Core service: `src/lib/dataService.ts` (functions: `recordContribution`, `initiateMoMoPayment`, `updateContributionStatus`)

**Receipts**: 
- **No dedicated receipt system** - payments are recorded with `transaction_ref` as reference only

**Invoices**:
- **No invoice generation** - this is a SACCO (Savings and Credit Cooperative) system that tracks contributions rather than invoicing

### 2. Who gets what notification and how does the system treat the payment?

**Notifications**:
- **No notification system exists** - only in-app toast-style UI feedback in `ContributionsPage.tsx`
- No push/email notifications

**Payment Treatment**:
- Payments get a status: `pending` → `confirmed` or `failed` or `reconciled`
- Elevated users (chairperson/treasurer) can review and confirm pending payments

### 3. How are the payments confirmed?

**Confirmation Flow**:
1. Payment submitted → status = `pending`
2. Elevated user sees pending contributions in UI (`ContributionsPage.tsx` lines 389-409)
3. User clicks "Confirm" or "Failed" button
4. `updateContributionStatus` function updates the status in database
5. Demo mode: auto-confirms after short delay (lines 507-512 in dataService.ts)

## Summary

Saccoup uses a contributions-based SACCO model rather than traditional invoice/receipt patterns. To add proper receipts, invoices, and notifications, new features would need to be developed.
