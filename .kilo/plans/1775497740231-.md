# Saccoup Payment System - Enhanced Workflow Plan

## User Requirements (Confirmed)

- **Confirmation Flow**: Option A - Pending payments appear, admin just confirms and enters amount received
- **Balance Display**: Clear visual showing paid vs amount due
- **Primary Payment Method**: Mobile money (MoMo push to chairman's number)

---

## Current Issues to Fix

1. **No "click to confirm" workflow** - Admin currently must enter all details manually
2. **amount_due not auto-filled** - When recording contributions, expected amount not pulled from group settings
3. **No pending payments queue** - Members can't submit pending payments for chairman to confirm

---

## Implementation Plan

### Phase 1: Fix amount_due Auto-fill (Bug Fix)

**File**: `src/components/saccoUp/ContributionsPage.tsx`

In `recordContribution` call, add `amount_due` from group's `contribution_amount`:

```typescript
// When recording, auto-fill expected amount from group settings
amount_due: selectedGroup.contribution_amount || parseInt(newContribution.amount),
```

### Phase 2: Pending Payments Queue (New Feature)

**Database**: Add pending payments table or use existing contributions with status

**UI Flow**:
1. Members submit payment (via MoMo push intent or form)
2. Payment appears in chairman's "Pending Confirmations" list
3. Chairman sees: member name, expected amount, date submitted
4. Chairman enters actual amount received → clicks "Confirm"

**Files to modify/create**:
- `src/components/saccoUp/ContributionsPage.tsx` - Add pending queue section
- `src/lib/dataService.ts` - Add functions for pending payment handling

### Phase 3: Clear Balance Display

**UI Improvements**:
- Column showing: Expected | Paid | Balance
- Green checkmark (✅) when fully paid
- Red balance amount when partial
- Color coding: green = good, yellow = partial, red = overdue

### Phase 4: Mobile Money Integration (Optional - for later)

- MoMo push webhook handling
- Auto-create pending payment when member sends money
- Chairman notification when payment received
